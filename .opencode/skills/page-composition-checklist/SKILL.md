# Page Composition Checklist

The verification gate. Run this **before** reporting any work as complete. A section is
not done because it looks right in `next dev` - it is done when every check below
passes.

This skill is the last of four and depends on the other three:

- `cyberpunk-design-system` - the palette, type, motion budget, and contrast numbers
  this checklist verifies against.
- `neon-tokens-tailwind4` - how tokens are registered in `@theme`; the source of the
  "no `tailwind.config.js`" and "no new dependencies" rules.
- `hud-ui-patterns` - the component recipes being reviewed. The a11y requirements here
  (focus rings, `aria-hidden` decoration, the drawer's `hidden` attribute) are the
  reasons those recipes are written the way they are.

Order matters: cheap automated checks first, then build, then manual browser checks.

## 1. Automated checks (run all three)

```bash
npm run lint
npm run typecheck   # tsc --noEmit - add this script if package.json lacks it
npm run build
```

- `build` is authoritative for CSS ordering and for catching client/server boundary
  mistakes. A page that styles correctly in dev can still break in production.
- Lint must be clean. `eslint-config-next/core-web-vitals` catches real accessibility
  issues (missing alt text, invalid nesting, unescaped entities).
- Never report success on `lint` alone.

## 2. Next.js 16 App Router correctness

Read `AGENTS.md` and the relevant guide in `node_modules/next/dist/docs/` before assuming
any API. Specific traps in this repo:

- **Root layout prop type.** `app/layout.tsx` uses the Next 16 typed-routes global
  `LayoutProps<"/">`. Do not "fix" it back to `{ children: React.ReactNode }` - that is
  a regression.
- **Do not remove the managed block** from `AGENTS.md`. It is regenerated by `next dev`
  and directs agents to the version-matched docs.
- **Server/Client boundaries.** Only two files may carry `"use client"`:
  `components/layout/site-nav.tsx` and `components/sections/terminal.tsx`. There is no
  `components/motion/reveal.tsx` - do not reintroduce it. A third requires an explicit
  justification to the user. Adding `"use client"` to `app/page.tsx` or any other
  section file is always wrong.
- **Never mutate a prop**, and never compute values with `Date.now()`/`Math.random()`
  during render of a Server Component - it breaks hydration. The footer year is the one
  sanctioned case (`new Date().getFullYear()`, no randomness).
- `app/page.tsx` is **composition only**: imports sections and places them. No markup,
  no classNames, no user-visible strings.
- All copy lives in `lib/content.ts`. A hardcoded string in JSX is a defect.

## 3. Accessibility

### Structure and landmarks

- One `<h1>` on the page (the hero headline). Section headings are `<h2>`; card titles
  `<h3>`. **No skipped levels.**
- Every `<section>` has an `id` and `aria-labelledby` referencing its heading.
- `<header>`, `<nav aria-label="Primary">`, `<main id="content">`, `<footer>` present.
- A skip link is the **first** focusable element in the layout:
  `className="sr-only focus:not-sr-only focus:absolute focus:z-[100] ..."`, targeting
  `#content`.
- Decorative layers (grid backdrop, corner ticks, status bars, scanlines, blinking
  cursor, `aria-hidden` SVG icons) are all `aria-hidden="true"` **and** non-focusable.
  Verify they are not `<button>`/`<a>`.

### Keyboard

- Tab through the entire page. Every interactive element must receive a **visible**
  `focus-visible` ring. On a near-black background the browser default ring is easy to
  miss - always specify `focus-visible:outline-cyan` with an offset.
- No positive `tabindex`.
- The mobile drawer's toggle is reachable and operable by keyboard, exposes
  `aria-expanded`/`aria-controls`, closes on `Escape`, and returns focus to the toggle
  on close.
- When the drawer is closed its links must be out of the tab order - the `hidden`
  attribute handles this; `opacity-0` alone does **not**.

### Contrast

Re-verify anything new against the palette table in `cyberpunk-design-system`:

- Text >= **4.5:1** (3:1 only for large text, >=24px or >=19px bold).
- Borders, focus rings, status dots, and other non-text UI >= **3:1**.
- **Never reduce text contrast with opacity modifiers.** `text-muted/60` fails. Use a
  darker token instead.
- Gradient text (`bg-clip-text`) must be checked - if legibility drops, drop the gradient.
- `--color-muted` must stay `#74839b` or lighter. `#6b7a8f` fails on `surface`.

### Screen reader

- Icon-only buttons have `sr-only` text.
- The terminal's animated text is fully present in the DOM; the cursor and the typing
  animation are `aria-hidden`.
- Status bars expose their value as **text**, not only as an ARIA value on a decorative
  element.
- `tabular-nums` on changing numeric values to stop layout jitter.

## 4. Reduced motion (mandatory, not optional)

Verify with OS-level reduced motion enabled, or DevTools
`Rendering -> Emulate CSS prefers-reduced-motion: reduce`.

- Every transition and animation collapses. `globals.css` carries a global guard; any
  animation not covered by it must add its own.
- **`components/sections/terminal.tsx` must render the final, complete, static output**
  when reduced motion is on - not a shortened animation, not an empty box.
- **Feature card hover** uses `hover:-translate-y-0.5` plus a tone border change and
  no shadow. Adding `hover:shadow-glow-*` puts a second glow tier on a page that
  already reserves its secondary tier for the hero mesh and the primary CTA.
- No information is conveyed by animation alone.

## 5. Responsive

Check at **375px**, **768px**, and **1440px**. Then also confirm nothing breaks at
~320px.

- No horizontal scrollbar at any width. Common causes: fixed widths, `whitespace-nowrap`
  on long content, the terminal `<pre>` (use `whitespace-pre-wrap break-words`), and
  long unbroken strings.
- Feature grid: `grid-cols-1 md:grid-cols-2 lg:grid-cols-3`.
- Hero headline scales with `text-5xl md:text-7xl lg:text-8xl` and must not overflow
  or break mid-word at 320px.
- Nav collapses to the drawer below `md`; links must not be duplicated in the tab order
  when the drawer is closed.
- Touch targets >= 44x44px for primary controls. The drawer toggle and nav links need
  adequate padding.
- Section rhythm stays `py-16` mobile / `py-24` desktop everywhere - verify no section
  was built with different spacing.

## 6. Dependency and asset discipline

- `package.json` dependencies are still exactly `next`, `react`, `react-dom`.
  `tailwindcss` and `@tailwindcss/postcss` stay in devDependencies.
- No new runtime library was added: no `clsx`, `tailwind-merge`, `framer-motion`,
  `lucide-react`, `cva`.
- **No `tailwind.config.js` exists.** Tokens live in `@theme` in `app/globals.css`.
- **No image files were generated or added.** Every visual is CSS. No `<Image>` needed
  unless real assets are supplied later.
- Icons are inline SVG, `aria-hidden`.

## 7. Final visual read

- Does the page look like one system, or a pile of parts? Reuse `hud-panel`,
  `neon-button`, `section-heading` rather than re-styling.
- Neon restraint: at most one strong glow per section.
- No lorem ipsum, no `Feature One`, no bracketed placeholders, no leftover
  `create-next-app` strings in metadata.
- `metadata.title` and `metadata.description` describe the real fictional product.
- The 5 boilerplate SVGs in `public/` are unreferenced and may be deleted.
- Git status shows only intended files. Do not commit unless asked.

## Reporting

State plainly what you verified and how (which commands, which viewport widths, whether
reduced motion was actually emulated). If a check could not be run, say so instead of
implying it passed.
